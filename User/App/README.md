# App 层

App 是最终机器人项目的编排层，负责把 Algorithm、BSP 和 Module 组装成云台、底盘、发射
和整车状态机。当前模板按此前要求不提供具体 App 源码，也不写死引脚、CAN 网络或参数。

## 应放在 App 的内容

- DR16 通道、开关和键鼠到目标值的映射；
- 云台 PID/LQR 模式选择；
- IMU 锁定与电机编码器锁定的目标源仲裁；
- 无力、普通、小陀螺、底盘跟随云台和自锁模式；
- 视觉、遥控和失联目标优先级；
- 裁判系统功率、热量和弹速约束；
- 发射许可、射频和弹仓策略；
- 云台板/底盘板角色和数据发布频率；
- 上电、自检、校准、运行、降级和急停状态机。

## 不应放在 App 的内容

- CAN/UART/SPI 收发细节；
- 电机协议字节；
- 通用 PID、滤波和底盘公式；
- BMI088 寄存器；
- 可复用的设备状态机；
- CubeMX 全局句柄查找。

这些分别属于 BSP、Module 或 Algorithm。

## 推荐项目拆分

```text
App/
├── app_robot/       整车生命周期和板角色
├── app_gimbal/      云台模式、目标仲裁和轴控制
├── app_chassis/     底盘模式、坐标变换和功率策略
├── app_shooter/     发射许可和裁判约束
├── app_input/       DR16/键鼠映射
├── app_safety/      心跳、降级、急停和故障锁存
└── app_config.h     项目功能选择，不保存驱动实现
```

只有开始具体车型项目时才创建这些目录。

## 编译期选择

DR16 安装板和拨弹盘安装板可以通过项目级宏选择，但宏只决定 App 组装：

```text
owner board: local Module
peer board: Robot Link snapshot
```

协议 Module 和设备 Module 不应因安装位置产生两套实现。

## 调度建议

- 高频：IMU、云台控制、电机更新；
- 中频：底盘解算、DR16、Robot Link；
- 低频：裁判解析、健康统计、OLED、灯效；
- 事件：USB、USART、CAN 中断只投递数据。

具体频率和优先级根据实车测量确定，所有 `elapsed_time` 来自单调时基且只有一个推进所有者。

## 安全启动顺序

1. 输出保持禁止；
2. 初始化 BSP；
3. 初始化并注册 Module；
4. 启动接收链路；
5. 等待有效传感器和电机反馈；
6. 完成零位与姿态校准；
7. 确认遥控/板间链路和安全开关；
8. 状态机显式允许后才使能执行器。

## App 完成标准

- 没有跨文件散落的可变全局变量；
- 每个子系统用对象保存状态；
- 模块交互通过输入快照和明确接口；
- 所有模式切换有进入/退出动作；
- 所有外部目标有在线、时效和权限检查；
- 故障路径输出确定且需要显式恢复；
- 调度周期、单位和坐标系写入接口名称或文档。
